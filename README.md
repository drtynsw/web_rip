# Лабораторная работа №3
## Тема: Оценка уязвимости системы
- **Цель работы**: создание веб-сервиса в бэкенде нашей системы для использования его в `SPA`
- **Порядок показа**: **Скриншоты 1-10** Через `insomnia`/`postman` показать коллекцию 10 запросов, выполнить GET списка `услуг` (с фильтром), добавить новую `услугу` с картинкой и видео, получить поля `черновика`, опубликовать `услугу`, получить `ленту` без ид, получить ленту по ид `?next=true`, поставить `лайк`, удалить `услугу`, зарегистрировать нового `пользователя`. **Скриншоты 11-13** Показать измененные данные через `select`, **Скриншоты 14-15** объяснить модели, сериализаторы.  **Скриншоты 16-17** Показать функцию-`singleton` где пользователь указан константой и использование этой функции в методах, показать `README` с описание методов и таблиц
- **Контрольные вопросы**: веб-сервис, REST, RPC, заголовки и методы HTTP, версии HTTP, HTTPS, OSI ISO
- **Диаграмма классов** с детализацией бэкенда (домены методов по `url` с интерфейсами, перечислить все методы, модели, таблицы БД, 4 страницы фронтенда). Зависимость доменов от моделей сделать вашему коду, также указать зависимость страниц от доменов.
- **Задание**: Создание веб-сервиса со всей итоговой бизнес логикой (кроме авторизации), подключение его к БД и тестирование в `insomnia`/`postman`

Создание **веб-сервиса** для получения/редактирования данных из вашей БД. Требуется разработать все методы для реализации итоговой бизнес логики вашего приложения. Для изображений `услуг` использовать `Minio`. В `README` проекта описать все HTTP методы и таблицы с их полями.

**Требования к веб-сервису**

Методы и `url` в `API` должны соответствовать `REST`. Для списка `услуг` (как в 1 лабораторной) нужно предусмотреть фильтрацию на бэкенде. Взаимодействие с БД через `ORM`. Записи в статусе `удален` на клиент не передаются.

Статусы нельзя менять с любого на любой: у `создателя` два разных метода, вернуть в `черновик` нельзя. В данной лабораторной пользователь `создатель` зафиксирован во всех методах - укажите его константой через функцию-`singleton`. Системные поля (ид, статусы, создатель и модератор, даты создания, формирования и завершения) передавать с клиента для изменения запрещено. Они вычисляются на бэкенде через авторизацию и бизнес-логику. В начале адреса каждого метода добавьте `/api`

**Домен услуги:**
- GET список с фильтрацией (только опубликованные). Признак 0/1 если создатель услуги совпадает с текущим пользователем 
- GET лента (только опубликованные)
- GET получения черновика (не более 1 записи для пользователя), ид не указывается
- POST добавление + добавление файлов изображения и короткого видео (как файлы а НЕ просто URL), название файлов сохраняются в полях БД, а сами файлы в `minio`. Названия файлов генерируются на латинице
- PUT публикации (смена статуса)
- DELETE удаление (только soft delete). Только услуги этого пользователя
- POST like (от текущего пользователя). Поле 0/1 (0 отменяет лайк, 1 ставит лайк)

**Домен пользователь:**
- POST регистрация
- POST аутентификация (заглушка для 4ой лабораторной)
- POST деавторизация (заглушка для 4ой лабораторной)


### HTTP-методы

#### Домен «Услуги» — `/api/attack_vectors`

| № | Метод | URL | Описание | Тело запроса | Ответ |
|---|---|---|---|---|---|
| 1 | GET | `/api/attack_vectors?discovered_year=1999` | Список с фильтрацией (только опубликованные). Признак `is_mine` 0/1 — создатель услуги совпадает с текущим пользователем | — | 200, массив услуг |
| 2 | GET | `/api/attack_vectors/feed?id=1&next=true` | Лента (только опубликованные). Без параметров — первая услуга, `id` — услуга по id, `id` + `next=true` — следующая после id. Из БД читается одна строка | — | 200, одна услуга; 404 |
| 3 | GET | `/api/attack_vectors/draft` | Получение черновика (не более 1 записи для пользователя), id не указывается | — | 200, черновик; 404 |
| 4 | POST | `/api/attack_vectors` | Добавление + файлы изображения и короткого видео. Файлы — в MinIO, их латинские имена — в полях БД | `multipart/form-data`: `title`, `image` (файл), `video` (файл) | 201, черновик; 400; 409 — черновик уже есть |
| 5 | PUT | `/api/attack_vectors/draft/publish` | Публикация (смена статуса черновик → опубликован) | JSON: `short_description`, `severity` (1–10), `discovered_year` | 200, услуга; 400; 404 |
| 6 | DELETE | `/api/attack_vectors/:id` | Удаление (только soft delete). Только услуги этого пользователя | — | 200; 403 — чужая; 404 |
| 7 | POST | `/api/attack_vectors/:id/like` | Лайк от текущего пользователя. `like`: 1 — ставит, 0 — отменяет | JSON: `like` | 200, услуга; 400; 404 |

### Таблицы БД

#### `users` — пользователи
| Столбец | Тип | Описание |
|---|---|---|
| id | int, PK | идентификатор |
| username | varchar(100), UNIQUE, NOT NULL | логин |
| password | varchar(255), NOT NULL | хеш пароля |

#### `attack_vectors` — услуги (векторы атак)
| Столбец | Тип | Описание |
|---|---|---|
| id | int, PK | идентификатор |
| title | varchar(150), NOT NULL | название |
| short_description | varchar(500), NULL | краткое описание (заполняется при публикации) |
| status | enum draft/published/deleted, NOT NULL | статус, только в БД |
| image_url | varchar(255), NOT NULL | имя файла изображения в MinIO |
| video_url | varchar(255), NOT NULL | имя файла видео в MinIO |
| severity | int, NULL | базовая опасность вектора атаки, 1–10 |
| discovered_year | int, NULL | год первой массовой фиксации |
| created_at | timestamp, NOT NULL | дата создания |
| published_at | timestamp, NULL | дата формирования (публикации) |
| creator_id | int, FK → users.id, NOT NULL | создатель |

#### `likes` — лайки (м-м пользователь — услуга)
| Столбец | Тип | Описание |
|---|---|---|
| id | int, PK | идентификатор |
| user_id | int, FK → users.id | кто поставил лайк |
| attack_vector_id | int, FK → attack_vectors.id | какой услуге |
